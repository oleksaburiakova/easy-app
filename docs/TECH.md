# Easy — технічна довідка

Для програміста, який оцінює якість застосунку. Стан на 27.11.2026.

## Що це
Easy — веб-застосунок (PWA) для телефона: людина проходить анкету, отримує калорійність за таблицею нутриціолога й збирає збалансовану тарілку з того, що є вдома. Грамовки заздалегідь пораховані нутриціологом під 4 рівні калорійності (дерево конструктора — `data/easy-tree.json`). Застосунок нічого не рахує «на льоту» й не показує калорій окремих тарілок.

Живий сайт — на Vercel; встановлюється на головний екран iPhone / Android.

## Стек
- **Next.js 15.5 (App Router) + TypeScript 5**, React 19. Без UI-бібліотек: власна дизайн-система (`styles/tokens.css`, `styles/components.css`, класи `ez-*`).
- **Хостинг — Vercel** (зараз безкоштовний Hobby). Кожен пуш у `main` збирається й викладається автоматично; попередню версію можна повернути одним натиском. Перед продажами потрібен комерційний тариф: обираємо між Vercel Pro і Cloudflare Workers (через OpenNext) — відкрите питання.
- **Відео — Vimeo**, PDF-гайди — статичні файли з власним переглядачем сторінок.
- Залежностей мінімум: у продакшні лише `next`, `react`, `react-dom`. `npm audit` — 0 вразливостей (PostCSS усередині Next примусово оновлено через `overrides`).

## Перевірки якості
- `npm run lint` — ESLint з правилами Next.js і TypeScript; запускається й під час `npm run build` (з помилками сайт не збереться), разом із перевіркою типів.
- `npm test` — 38 автотестів (Vitest): калорійність за таблицею; грамовки й «≈ готової»; заміни сиру за таблицею нутриціолога; правила конструктора («солодке через день», добір білка, основи страв); прохід **усіх ≈ 3 000 комбінацій тарілок** з дерева (у кожної є фото, основа чи білок, коректна назва).
- `npm run check-tree` — цілісність дерева після кожної зміни даних.
- Стилі: шари `tokens` → `components` → `glass` → `app.css`, статичних інлайн-стилів немає (лише динамічні значення). Перенос перевірено попіксельним порівнянням 88 екранів і станів до / після.

## Етап 2 — як буде зроблено (грудень)
- **Акаунти — Supabase** (Postgres, регіон ЄС): вхід за 6-значним кодом із пошти, без паролів. Дані з `localStorage` переносяться в акаунт при першому вході.
- **Захист даних — Row Level Security**: кожна людина читає й змінює лише свої рядки; перевіряється в базі, а не в браузері. Ваги й даних про здоров'я не збираємо; в аналітиці — анонімно.
- **Оплата — еквайринг (WayForPay або monobank) на ФОП власниці.** Доступ на 1 / 3 / 6 місяців разовою оплатою; доступ відкриває сервер лише після вебхука платіжки з перевіреним підписом. Промокоди й подарункові сертифікати — у базі.
- **Закриті відео**: Vimeo з забороною показу поза доменом Easy; сторінка уроку віддається лише з активним доступом (перевірка на сервері).
- **Ключі — лише на сервері** (змінні середовища Vercel), у репозиторії їх немає. Щоденні резервні копії бази — на платному тарифі Supabase Pro (≈ $25/міс).
- Адмінка для власниці: продажі, користувачі, де кидають конструктор.
- Перед запуском: автотести входу, оплати й доступу; перевірка безпеки; за бажанням — незалежний аудит.

## Дані про здоров'я — особлива категорія
Трекер (настрій, енергія, ситість, тренування, кроки, вода) і харчування за методикою нутриціолога — дані, пов'язані зі здоров'ям: за GDPR (ст. 9) і законом України «Про захист персональних даних» (ст. 7) — чутлива категорія. Їх можна обробляти лише з явної окремої згоди й з посиленим захистом. Ваги не збираємо.

- **Зараз (етап 1)** усі дані — лише в телефоні користувачки (`localStorage`), на сервер нічого не передається.
- **Мінімізація (етап 2):** на сервер — лише потрібне для акаунта й оплати (email, калорійність, тарілки, підписка). Трекер самочувствія (настрій, енергія, ситість) пропонуємо лишити тільки в телефоні — найчутливіші дані не потрапляють на сервер (рішення погоджує власниця).
- **Окрема явна згода** при реєстрації на обробку даних про харчування й самопочуття — окремо від оферти, не відмічена заздалегідь; відкликання згоди й видалення всіх даних — однією кнопкою в профілі.
- **Захист:** сервери в ЄС; шифрування при передачі (https) і зберіганні (Supabase); Row Level Security; в аналітиці — лише знеособлені агреговані дані; у рекламні пікселі (Meta) — жодних даних про здоров'я.
- **Юридично:** власниця даних (контролер) — ФОП власниці продукту; політика конфіденціальності з окремим розділом про дані здоров'я; договори про обробку даних (DPA) з Supabase і хостингом; порядок дій у разі витоку; формулювання «не медична послуга, не ставить діагнозів» (дисклеймер уже є). Перевіряє юрист.
